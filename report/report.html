AIA Brochure Q&A: a grounded RAG system with an agent

LLM course capstone · code: github.com/Calvinkub/aia-brochure-rag · chat model gemma-4-E4B-it, embeddings bge-m3 via the class proxy

1. Problem and audience

Insurance brochures hold the facts a customer needs (waiting periods, issue ages, benefit percentages, fees), but those facts sit in tables and disclaimers spread across many PDFs. A general-purpose chatbot answers from memory, which for a specific Thai product means a confident guess. This project answers questions about AIA Thailand products only from the brochure text, cites the page, and says "the brochures do not say this" when the evidence is absent.

Who it is for: a prospective policyholder or an advisor who wants a fast, checkable answer, not a recommendation. It is a course project, not insurance advice. The brochures are dated 2019–2022 and may be out of date.

Why a reference app cannot do this: the corpus is 16 public AIA Thailand PDFs, downloaded by scripts/fetch_corpus.py. Fifteen yield usable English text (94 pages, 290 chunks); the closed-book model has no reliable knowledge of them, and the evaluation below shows it (7% accuracy when forced to guess).

Hybrid retrieval was chosen over dense-only because brochure questions mix exact tokens (numbers, product names) with paraphrase; reciprocal-rank fusion needs no score calibration. The API key and base URL come only from the environment, and no secret is committed.

3. Evaluation

Test set (eval/gold.jsonl): 28 answerable questions, each with a verbatim evidence quote, gold product and page, and required keywords; plus 6 unanswerable questions that are topically close but absent from the corpus (for example Vitality reward tiers). eval/check_gold.py verifies every evidence quote against the extracted page text and checks that the unanswerable terms do not occur in the corpus. Questions were drafted with AI assistance from the brochure text; the quote check keeps the labels honest, but they are not independent human labels.

Metrics. Retrieval: hit@k and MRR, where a hit is a top-k chunk from the gold product on a gold page. Answers: accuracy (all gold keywords appear as whole tokens), false abstain (answerable question declined), abstain on unanswerable, cites gold page, and citation verified (share of citations whose quote really occurs in the passage). All runs use temperature 0 with an on-disk cache so results reproduce.

Baselines. (a) closed-book, may abstain; (b) closed-book, forced to guess; (c) BM25 RAG with the same chunks. The first scores 0 only because the model refuses everything, so (b) is the informative closed-book baseline.

  • Retrieval is what makes it work. Forced-guess closed-book gets 2 of 28 right and answers 3 of 6 unanswerable questions anyway. With retrieval: 26 of 28, and no answer to any unanswerable question.
  • Measured improvement over the naive default (BM25, same chunks): hybrid raises MRR 0.832 to 0.882, hit@1 0.79 to 0.82, citation-verified rate 0.95 to 1.00, and removes the one false abstain. With n = 28 this is one or two questions: a direction, not a significant result.

4.3 Chunking experiments

The baseline E0 cuts fixed 180-word windows: 74% of chunks end mid-sentence and about 15% of the text is disclaimers repeated on every page. Four techniques came from a NotebookLM literature pass (web sources; figures not independently verified) and were each measured on the same gold set. Late chunking was skipped because it needs a different embedding model than the proxy offers; semantic chunking was skipped because it reportedly fragments short text.

No variant clearly beats the baseline. Accuracy moves by ±1 question (25–27 of 28) and MRR by 0.01–0.04, all inside noise for n = 28. E1 cuts mid-sentence endings from 74% to 13% of chunks but did not raise accuracy. E2 and E3 fixed one question (A24) but lowered the share of verifiable citations from 1.00 to 0.88–0.92; the cause was not investigated. E4 with dense-only retrieval was the best retriever (hit@3 = hit@5 = 1.00, MRR 0.923), but its answers were not evaluated, to avoid tuning further on the same questions, so this is a hypothesis for a fresh question set, not a result. E0 stays the default; the variants are opt-in.

5. Failure cases

idquestionwhat happenedcause
A07How many severe-stage critical illnesses does AIA CI Care cover?Answered 44; the gold label says 40.The brochure contradicts itself: page 1 says "Cover 44 severe stage critical illnesses", the page-2 table header says "Severe Stage (40 Diseases / Treatment)". The gold label follows the table; the model followed page 1, which is a supported reading. This is a source conflict, not a hallucination. The ideal behaviour is to flag the conflict, and the system does not.
A24Which premium payment periods can be chosen for Infinite Wealth Prestige?Answered with top-up payment frequency (monthly, quarterly).The gold chunk (page 3) ranked 5th; the model answered from a higher-ranked passage that uses a different sense of "payment period".
A17 (floor only)Maximum income tax deduction for Smart Select?False abstain.The min_score = 0.65 floor dropped the evidence chunk.
Correction on record. I first diagnosed A07 as the model inventing "44" because a flattened table lost its structure. Re-reading page 1 showed that the number is in the brochure. The diagnosis, and the README that repeated it, were wrong and have been corrected. The lesson for the evaluation: a label can be the contested side, so each failure needs a look at the source before blaming the model.

6. Limitations and next steps

  • Small, self-built eval, tuned on itself. Chunk size, retrieval mode and min_score were chosen by looking at the same 34 questions. There is no held-out set, so the shipped numbers are optimistic, and one-question differences are noise.
  • Keyword scoring is a proxy. It can credit the right number in the wrong context and miss a correct paraphrase. One gold keyword was a word stem that wrongly failed a correct answer; it was changed to a full word. No LLM judge was used.
  • Conflicting sources are not flagged (A07), and PDF tables flatten with the default parser. The table parser (E2) did not measurably help here, so the effect of flattening is untested rather than disproved.
  • English brochures only. Three files labelled English are actually Thai and extract as garbage, so they are filtered out; some products (term life, endowment, pay-life) are thin or missing.
  • The agent is not quantitatively evaluated. It was exercised by hand (multi-step comparison, argument-rejection tests); in one manual run it multiplied by hand instead of calling calculate.
  • One model family does everything, with no independent judge, and depends on the class proxy. The repo was built in one working session, so its history is a short run of logical commits.

Next steps: detect and report conflicting figures across retrieved passages; test dense-only parent-child retrieval on a fresh question set; find out why table-based variants lower citation verification; write a larger held-out gold set that the system was not tuned on; add an agent gold set; support Thai.
